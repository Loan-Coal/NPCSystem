## Findings

### [L9-10] `make demo-run ARGS=--dry-run` crashes on Windows default console codec (U+2192)
**Severity: LOW · Confidence: Confirmed** *(Windows-only environmental; same root cause as ISSUE-100)*

The scripted scenario narration emits `→` (U+2192, e.g. "Correction is LOCAL → the graph proves
it" and "identical seeds → proving replayable gossip"). On Windows the default stdout codec is
cp1252 (`charmap`), which cannot encode U+2192, so the process aborts mid-run:

```
  [ACT 8] Determinism proof. Same tick_override=42 called twice...
Traceback (most recent call last):
  File "...\demo_game\run.py", line 625, in <module>
    main()
  ...
    return codecs.charmap_encode(input,self.errors,encoding_table)[0]
UnicodeEncodeError: 'charmap' codec can't encode character '→' in position 114: character maps to <undefined>
```

Proof it is encoding-only, not a logic break:
```
$ PYTHONIOENCODING=utf-8 python -m demo_game.run --dry-run   # exit 0
  === Demo complete. 12 acts. ... ===
  [done] 0.0s elapsed
```

**Real-everywhere?** No — Linux/macOS default to UTF-8 stdout, and the CI container is Linux,
so this does not break the demo there. It only bites a Windows operator running the demo at a
raw console. Classify LOW / log-only.

**One-line fix sketch:** in `demo_game/run.py`, reconfigure stdout to UTF-8 at startup
(`sys.stdout.reconfigure(encoding="utf-8")`, guarded for the attr) — or replace the `→`
literals in narration strings with ASCII `->`. Either makes the default-console invocation green
on Windows. (Tracked as ISSUE-100.)
