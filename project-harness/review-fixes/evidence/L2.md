## Findings

### [L2-01] `TraitReadPort` has zero implementors and is never wired — DEC-137's "slice-2" never landed
Severity: MEDIUM · Confidence: Confirmed
**Evidence:** `engines/ports/trait_read_port.py:9` documents an implementor "in the graph.repositories layer (slice 2 wiring)"; no such class exists (no `graph/repositories/*trait*` file). `engines/emotion/emotion_updater.py:56,76,152-155` takes `trait_reader: TraitReadPort | None = None`; when `None` — the only reachable state — `_get_model_for` always returns `self._model`, so `TraitModulatedEmotionModel` is dead in production. `trait_reader` in `src/npc_engine/api` → 0 hits; no dependency module constructs one. `project-harness/DECISIONS.md:190-204` (DEC-137, 2026-06-19) deferred it to "slice-2"; ~2.5 months later it is still unimplemented.
**Why it matters:** A full Protocol file, an injected-but-unreachable parameter, and an unexecutable model class. Per-NPC trait-modulated emotion — the entire point of DEC-137 — silently never happens; every NPC gets the shared fallback model. A product gap hiding behind code that reads as "already handled."
**Fix sketch:** Either implement `Neo4jTraitReadRepository` and wire it in `api/dependencies_stores.py`, or delete the port, the parameter and the `_get_model_for` branch and log the deferral in `ISSUES.md`.

### [L2-02] 34 of 44 ports (77%) fail the repo's own DIP threshold — systemic over-abstraction
Severity: HIGH · Confidence: Confirmed
**Evidence:** Port sizing table above, mechanically counted. 34 Protocol classes have exactly 1 implementor and 1–2 callers; many (`ChapterGraphPort`, `EventGraphPort`, `EconomyGraphPort`, `EmotionGraphPort`, `GroupGraphPort`, `MemoryGraphPort`, …) have exactly one caller — one concrete class, one consumer, zero substitutability exercised anywhere in the tree.
**Why it matters:** 39 files, ~170 Protocol methods and 39 matching `Neo4j*Repository` classes exist largely to satisfy a rule most of them do not meet. Each is a file a contributor or an agent must open, understand and keep in sync with its sole implementor, for polymorphism that is never used. This is the largest "fewer moving parts" lever in L2's scope.
**Fix sketch:** Needs a human call (public-interface change → ask-gate). Either (a) collapse each single-implementor/single-caller port into direct injection of the concrete `Neo4j*Repository` — which is what CLAUDE.md's own below-threshold rule prescribes — removing ~30 files; or (b) if the ports pre-stage the planned Kùzu graph-backend swap (`OD-Ship-graph`), record that as an explicit threshold waiver in DECISIONS.md. No such waiver exists today, so the state reads as violated rather than chosen.

### [L2-03] Two god-ports pair a wide interface with a single caller
Severity: MEDIUM · Confidence: Confirmed
**Evidence:** `engines/ports/chapter_port.py:21-70` — `ChapterGraphPort`, 9 methods, 1 implementor (`graph/repositories/chapter_repository.py`), 1 caller (`engines/chapter/chapter_engine.py`). `engines/ports/quest_generation_port.py:17-76` — `QuestGenerationGraphPort`, 11 methods, 1 implementor, 2 callers.
**Why it matters:** A 9–11 method Protocol should buy substitutability across several implementations or consumers; here it is dictated by and consumed by one class. None of ISP's benefit, all of its cost.
**Fix sketch:** Fold into L2-02. Concrete injection (`ChapterEngine.__init__(self, chapter_repo: Neo4jChapterRepository)`) is equally testable without the interface ceremony.

### [L2-04] Two ports import graph-owned types — one an explicitly private Protocol — so the abstraction leaks what it exists to hide
Severity: MEDIUM · Confidence: Confirmed
**Evidence:** `engines/ports/event_port.py:19-20` imports `RoutineOverridePlan` from `graph/event/event_emission_service.py` and `_EventNode` from `graph/event/event_writer.py`. `_EventNode` is declared at `graph/event/event_writer.py:20` as `class _EventNode(Protocol):` — the underscore is the module's own signal that it is private — yet it is used as a parameter type at `engines/ports/event_port.py:33`. Likewise `engines/ports/relation_read_port.py:21` (`RelationPhaseRow` from `graph/relations/relation_phase_reader.py`) and `engines/ports/scheming_port.py:22` (`ActiveSchemeProgress`, `SchemeRecord` from `graph/intrigue/scheme_reader.py`). These are downward imports (engines rank 5 → graph rank 2), so `check-layers` correctly does not flag them; the defect is ownership, not direction. `event_port.py:6-7`'s own docstring says engines use the Protocol "instead of importing graph writers."
**Why it matters:** If `_EventNode` changes — and being private, nothing outside its file should treat it as stable — `engines/ports/event_port.py`'s public signature changes with it. The dependency inversion the port exists to create is quietly undone through the type import.
**Fix sketch:** Have the port own its DTO (defined in `event_port.py` or a shared `engines/ports/_dtos.py`) and have the graph writer conform to it, rather than the port importing the writer's private type.

### [L2-05] Three sibling quest Protocols redeclare identical methods instead of sharing a base
Severity: LOW · Confidence: Confirmed
**Evidence:** `engines/ports/quest_port.py:21-124` — `QuestLifecycleGraphPort` (`get_quest_state`, `update_quest_node_status`), `QuestOfferGraphPort` (`get_quest`, `update_quest_node_status`), `QuestRewardGraphPort` (`get_quest_state`, `emit_lifecycle_event`); each redeclares a method a sibling in the same file already declares, all satisfied by the same implementor `graph/repositories/quest_repository.py`.
**Why it matters:** A signature change must be made in 2–3 places with no type-checker cross-check; structural typing lets the redeclarations drift silently.
**Fix sketch:** Extract the shared methods into one small base Protocol the three compose, or record "ISP over DRY" as a deliberate choice in DECISIONS.md.

### [L2-06] CLAUDE.md's inline layer diagram omits `observability/` and `setup/`, both ranked and enforced
Severity: LOW · Confidence: Confirmed
**Evidence:** `scripts/check_layers.py:28-49` `LAYER_RANK` includes `"observability": 1` and `"setup": 1` with a comment at `:46-48` (SHIP-03/DEC-127). `project-harness/CLAUDE.md`'s Architecture section — explicitly billed as "the one rule this file states in full" — lists 16 packages and omits both.
**Why it matters:** CLAUDE.md says layer lists are pointers because "a copy here is a copy that rots (DEC-249)", but this diagram is an inline copy and is already stale for 2 of 18 ranked packages — the exact drift DEC-249 exists to prevent.
**Fix sketch:** Add the two rows, or replace the inline diagram with a pointer to `LAYER_RANK` per the file's own policy.
